# P5 · TV 遥控器方向键失灵修复（手机遥控器适配）— 交付说明

**报障**：手机遥控器控制 TV APK，上下左右无法选择，只有「确定」键有用。
**结论**：需要独立适配，但**主修复在网页侧**——已上线，重装 APK 前就能生效；APK 壳另有加固，经 CI 出新包。
**提交**：d32f2b9（4 files +143/-10）· 网页已覆盖发布（链接不变）。

## 一、根因

| 层 | 问题 | 后果 |
|---|---|---|
| 网页 tvnav（主因） | 只认现代键名 `ArrowLeft/Up/…`；老安卓 WebView（电视盒子 System WebView 常停在 Chrome 54 以前）的方向键名是旧 DOM3 命名 `Left/Up/…`，部分遥控只发 keyCode | 方向键全部失灵 |
| 确定键 | Enter 的旧命名就是 `Enter`，恰好匹配 | **只有确定键能用**（与你实测完全一致） |
| 触摸板遥控（次因） | 触摸板模式只发触摸事件、不发按键 | 即使键名修好，滑动仍无响应 |
| APK 壳 | WebView 未保活焦点，部分盒子把方向键吃在 Activity 焦点链路 | 键事件到不了网页 |

## 二、修复（三路互为兜底）

1. **网页按键归一化 `normKey()`**：现代键名 / 旧键名（`Left` 等）/ 纯 keyCode 三路兼容；
   菜单焦点导航与**对局内遥控动作映射**全部走归一化（对局中方向键=跳/蹲/左右移动）。
2. **触摸板兜底**（TV 模式）：滑动 = 方向键（焦点跟着走），轻点空白 = 确认当前焦点，
   点在按钮上 = 原生点击。任何手机遥控器形态都能操作。
3. **APK 壳加固**（`tv-app/.../MainActivity.kt`）：WebView 可聚焦 + requestFocus 保活；
   DPAD/OK 键显式 `dispatchKeyEvent` 转发给网页；缓存戳升 `v=1.2`。
   → 新 APK 由 GitHub Actions（tv-apk.yml）自动出包，装不装都行——**网页修复现在已生效**。

## 三、验证实证（探针 10/10）

| 链路 | 结果 |
|---|---|
| 现代键名 ArrowDown | ✅ 焦点移动 |
| 老键名 `Left`（Chrome 54 前） | ✅ 焦点移动 |
| 纯 keyCode 39 / 40 / 38（key=Unidentified） | ✅ 焦点移动 |
| 触摸板上滑/下滑/右滑/左滑 | ✅ 焦点移动 |
| 确定键：`Enter` / keyCode 23（DPAD_CENTER）/ 触摸板轻点空白 | ✅ 均触发确认 |

## 四、你现在怎么用（给用户的最短路径）

1. **不用等新 APK**：电视上现有的 TV APK 直接重新打开游戏（或断电重启）即可——
   方向键修复走的是线上网页，自动生效。**先试遥控方向键**。
2. 若手机遥控 App 有「按键模式 / D-pad 模式」优先用它；触摸板模式也已支持（滑动=方向）。
3. 想换新 APK（含按键转发加固）：GitHub Actions 的 tv-apk.yml 出包后下载安装即可（同一链接游戏）。

## 五、边界说明

- 触摸板滑动在 TV 模式下接管为焦点导航（原本也没有别的滚动需求）；手机/平板浏览器不受影响。
- 游戏进行中方向键 = 游戏动作（跳/蹲/左右），菜单/结算/设置 = 焦点导航，与原设计一致。
