# TV 遥控失灵 · 根治（p12）

## 根因（这次挖到底了）

上一轮修的是焦点交互层，但你的遥控器还是不行——因为问题不在焦点逻辑，而在**脚本根本没跑/按键根本没到**：

1. **致命根因：JS 语法超出电视内核**。电视盒子的浏览器内核常停在 Chrome 60–79，而线上脚本里有 **74 个 `?.` + 77 个 `??`**（ES2020 语法，Chrome 80 才支持）。内核解析脚本时直接抛 SyntaxError，**整个脚本一条都不执行**：关卡不渲染、按钮全死、遥控器按什么都没反应——这就是「遥控器无法自动」。
2. **次要根因：按键链路靠赌**。按键从遥控器到网页要过「WebView 焦点链路」这道不确定的关卡（焦点被系统吃掉时按键在半路被吞），之前是「先试 WebView、失败再兜底」的双路结构，哪条都不保证通。

## 根治手段

| 链路 | 之前 | 现在 |
|---|---|---|
| 脚本兼容 | vite 默认输出 ES2020 语法，老内核直接死 | **全链降级 ES2015**（dev/build/依赖预构建），实测线上 `?.`/`??` 归零，Chrome 55+ 都能跑 |
| 运行时 API | `padStart` 等新 API 可能缺 | 内联兜底 polyfill；`randomUUID` 代码内已自带降级 |
| 极老内核 | 死寂白屏/死页面 | `<nomodule>` 故障提示（人话告诉用户去更新系统） |
| 遥控按键 | 双路转发，赌 WebView 焦点状态 | **单一确定性管道**：每个按键由原生直接注入网页处理，与焦点状态无关，永不卡死 |
| 长按 | 按一下动一下 | **长按自动连发**（腾讯视频同款手感） |

## 配套（上一轮已做的焦点体系保留）

焦点自动落位、焦点记忆（从哪来回哪去）、弹层困焦点、金色大光环——New TV 极光（腾讯视频 TV）那套规则不变。
