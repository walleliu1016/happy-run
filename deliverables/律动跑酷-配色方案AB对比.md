## 0. 结论先行

1. **两版都解决同一个真问题**：现状是「浅色信息外壳（菜单/设置/档案/结算）+ 霓虹暗色舞台（游戏/海报/横幅）」双轨割裂，TV 上从菜单切到游戏像换了两个 App。A / B 都把 **9 个屏统一收敛到一套暗色语义色板**，差异只在气质（冷 vs 暖）。
2. **两版都是深底，不是漏出浅色版**。理由：TV 在暗客厅、2.5–3.5m 观看距离下，大面积浅底会刺眼且让霓虹舞台显得发灰；暗底 + 少量高饱和强调是这个载体和这个品类的正确解。
3. **两版都避开被否决的 V2 老路**：不用粉彩、不用圆胖多色、不做低龄糖果卡通；B 是「深炭底 + 能量橙 + 珊瑚红 + 青柠点睛」的成人化运动科技感。
4. **推荐 A（深空霓虹）**：延续 v1 青/紫/金/粉霓虹语汇，是「统一」而非「推翻」，改动面与风险最低；B 适合你要「一眼看出换了新的」。
5. **换配色不等于改一行 CSS**：现状 110 个硬编码 hex、248 次出现，落地前必须先做 12 个 `--c-*` 语义 token 化，否则改色要动 248 处。详见 §6。

### 为什么用规格稿（SVG）而不是生成图

配色评审要求**精确色值 + 版式完全一致**。AI 生成图会连构图、圆角、字重一起变，你看到的差异就分不清是配色好还是排版好，评审结论不可用。本次两张图由同一套 SVG 模板 + 两套色值变量生成（`/tmp/p15-palette-gen.mjs`），**元素位置、尺寸、文字、组件 1:1 相同，只有填充色不同** —— 这是唯一能做有效 A/B 对比的形式。

> 两张图是**规格标注稿，不进引擎**；图内文字仅为标注。真正进引擎的资源一律无文字（已确认红线）。

## 1. 两版 side-by-side 对照

| 维度 | **A 深空霓虹 DEEP NEON** | **B 熔岩运动 LAVA KINETIC** |
|---|---|---|
| 气质 | 冷 / 电子竞速 / 夜场霓虹 | 暖 / 健身房 / 体感能量 |
| 设计动作 | **统一**（把浅色外壳收进现有霓虹体系） | **换气质**（连主色语汇一起换） |
| 主强调 | 青 `#22E1FF` | 能量橙 `#FF7A1A` |
| 次强调 | 电紫 `#7B2FF7` | 珊瑚红 `#FF4D4D` |
| 判定 Perfect | 薄荷绿 `#34D399` | 青柠 `#C6FF4D` |
| 底色 | 深空蓝 `#080B16` | 暖炭 `#120D0B` |
| 与 v1 关系 | 延续（青/紫/金/粉全部保留） | 重定（只保留焦点金） |
| 改动面 | 小：游戏屏几乎不动，主要改 4 个浅色屏 | 大：9 屏 + 海报/横幅/HUD 全换 |
| 观感变化 | 中等（解决割裂，但「像原来的」） | 明显（一眼是新产品） |
| TV 3m 观看 | 冷色高饱和，边缘清晰、不刺眼 | 暖色更醒目，长时注视更易疲劳 |
| 4K 大屏风险 | 青紫发光面积需控制，防过曝 | 同左，橙红面积更大，风险略高 |
| 图标兼容 | Joy 蓝柄 `#2f80ff` 在冷底上自然 | **Joy 蓝柄对比度下降，需加描边或换色** |
| 历史风险 | 最低（未推翻用户已确认的霓虹调性） | 中（V2 糖果卡通重设计曾被否决，B 已刻意避开但仍是新方向） |
| 适合 | 稳、快、TV 优先、不想返工 | 想借改版做一次品牌气质升级 |

**推荐 A，依据三条**：① 你否决过 V2 的糖果卡通重设计，说明现有霓虹暗色调性是被认可的，A 不推翻它；② 游戏屏本来就是这套色，A 的改动集中在浅色外壳 4 屏，返工面最小；③ 冷色在 3m 观看、暗客厅环境下长时更舒适。**选 B 的唯一强理由**是「要一眼看出换了一套新 UI」—— 这是产品判断，不是设计判断，得你定。

> 不建议第一版就做「A 的体系 + B 的主色」混搭：会破坏 12 个语义 token 的对比度配平，且两套强调色的发光/过曝控制要重新算。要混搭，等选定主版后再单独开一轮。

## 2. 精确色值表（12 个语义 token）

| token | 用途 | **A 深空霓虹** | **B 熔岩运动** |
|---|---|---|---|
| `--c-bg` | 全屏底 | `#080B16` | `#120D0B` |
| `--c-surface` | 卡片 / 分组 / 弹层 | `#131A2C` | `#211812` |
| `--c-surface2` | 悬浮 / 按下 / 分隔区 | `#1D2740` | `#31241B` |
| `--c-ink` | 主文字 | `#F2F6FF` | `#FFF6EC` |
| `--c-ink2` | 次文字 | `#9AA7C2` | `#BFAE9E` |
| `--c-brand` | 主强调 / 主按钮 / 进度 | `#22E1FF` | `#FF7A1A` |
| `--c-accent` | 次强调 / 教练标签 | `#7B2FF7` | `#FF4D4D` |
| `--c-gold` | 得分 / 星级 / 连击 | `#FFD60A` | `#FFC233` |
| `--c-danger` | 失败 / PK / 破纪录 | `#FF375F` | `#C4243B` |
| `--c-success` | 判定 Perfect / 连接成功 | `#34D399` | `#C6FF4D` |
| `--c-daily` | 今日挑战 | `#1F8A4C` | `#4A6B14` |
| `--c-focus` | **TV 焦点环（已确认，两版相同）** | `#FFB020` | `#FFB020` |

- 两版各自 12 个 token **无重复色值**（B 的 `danger` 与 `accent` 已刻意拆开，避免改一个影响另一个）。
- 关卡海报 / 横幅的渐变属**装饰色**（插画位图），不入语义 token；落地时按屏分组管理即可。
- 深底上的分隔线统一 `1u rgba(255,255,255,.12)`、投影 `0 18u 42u rgba(0,0,0,.35)`；**不能直接沿用浅色外壳的 `rgba(0,0,0,.07)`**，否则暗底上看不见。

## 3. 对比度实算（WCAG 2.1 相对亮度，非估算）

脚本按 WCAG 公式逐色计算，取「浅字 `ink` / 深字 `bg`」中对比度更高者作为该色底上的推荐文字色：

| 色对 | A | B | 判定 |
|---|---|---|---|
| `ink / bg` 主文字 | **18.14:1** | **18.05:1** | AAA |
| `ink2 / bg` 次文字 | **8.11:1** | **8.97:1** | AAA |
| `brand` 上推荐文字 | 12.42:1（深字） | 7.40:1（深字） | AAA / AA+ |
| `accent` 上推荐文字 | 5.40:1（浅字） | 5.90:1（深字） | AA |
| `gold` 上推荐文字 | 13.90:1（深字） | 11.96:1（深字） | AAA |
| `danger` 上推荐文字 | 5.57:1（深字） | 5.36:1（浅字） | AA |
| `success` 上推荐文字 | 10.21:1（深字） | 16.37:1（深字） | AAA |
| `focus` 焦点环 | 10.73:1 | 10.55:1 | AAA |

**使用边界（写进落地规格）**：`accent` / `danger` 只有 5.3–5.9:1，属于 AA 而非 AAA —— **只用于大字号、图标、描边、徽章**，不得承载 B2 24u 以下的正文小字。所有正文一律 `ink` / `ink2` 落在 `bg` / `surface` 上（≥8:1）。焦点环 `#FFB020` 对比 10.5:1 以上，TV 3m 可辨。

## 6. 落地前提（选完版之后的第一件事，不是改颜色）

1. **先做语义 token 化**：在 `:root` 建 12 个 `--c-*`，把 248 处硬编码 hex 逐处替换；现状 `:root` 只有颜色 + `--radius:22px` + `--shadow` + `--font`，无 spacing/type/z-index token，建议与版式规范 §8 的 token 一起一次性建齐。
2. **暗底化的配套替换**：分隔线 `rgba(0,0,0,.07)` → `rgba(255,255,255,.12)`；`--shadow: 0 12px 40px rgba(0,0,0,.08)` → `0 18u 42u rgba(0,0,0,.35)`；`--blue-soft:#e8f1fd` 浅底 → `--c-surface2`。
3. **老内核 CSS 降级同步做**：`:has()` / `cqw` / `aspect-ratio` / `inset` 换成显式类名 / 固定档 / `padding-top` 百分比 / 四值写法；`clamp()` 降级为离散档固定 px（Chrome <79）。否则换完色在电视上仍是「脚本跑起来了但样式是废的」。
4. **逐级放量**：先改 1 个屏（建议菜单）出基准图 → 确认 → 再推其余 8 屏 + 弹层。不要 9 屏一起改。

## 7. 需要人工精修 / 合规确认（不承诺「生成即可用」）

- **两版**：SVG 里的海报、横幅、HUD 均为**规格示意**，不是最终素材；真正的发光/粒子贴图、复杂纹理插画需单独产出并人工精修，透明底、发光留白 ≥20%、叠加模式 `screen`、出 `@1x`/`@2x`。
- **B 版专属**：Joy 图标蓝柄 `#2f80ff` 在暖炭底上对比度下降，需加 `1u` 浅色描边或改冷色；暖色大面积在 4K 上要控制过曝。
- **两版**：现有大量 emoji 图标在暗底上饱和度与两版语义色不统一，建议随下一轮 C 图标家族一起换成 SVG symbol（32/48/64/96u 四档、小档单独简化）。
- **对比度数字**由脚本按 WCAG 2.1 公式实算，但落地到真实字体渲染（字重、抗锯齿、TV 面板色域）后需用取色工具复核一次。
- 规格稿内文字仅作标注，**进引擎资源不得含任何文字**。
