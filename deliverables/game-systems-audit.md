# 律动跑酷 · 游戏系统缺口审计（用户内容 / 进度 / 排名 / PK）

> 2026-11-22 · 从游戏设计角度盘点「单局体验」之外的长期留存系统。
> 现状实证：全游戏 localStorage 只有 2 项——装扮 `wu.look`、校准 `wu.calibMs`。

## 一、结论

游戏当前是「单局体验完整、长期动机为零」：判定/连击/评级/星级/分布条都有（r22 已补齐），
但没有存档、没有进度、没有记录、没有账号、没有排行、没有 PK——玩家打完一局没有留下任何东西。

留存三层循环（核心→元→社交）中，**元循环和社交循环整体缺失**。
P0 本地档案层不需要任何后端即可落地；P1 影子 PK 是天天跳绳都没有的差异化点；
P2 云端（账号/榜单/赛季）需要后端选型，且必须先解决反作弊。

## 二、现状盘点（代码实证）

| 项 | 现状 |
|---|---|
| 持久化 | 仅 `wu.look`（装扮）、`wu.calibMs`（校准偏移） |
| 成绩 | 每局结算完即丢弃，无最佳成绩（PB）、无历史 |
| 关卡 | 5 关 + 自由练习，海报墙入口；无通关存档、无解锁机制 |
| 账号/云 | 无。TV APK 与手机浏览器是两个独立 localStorage，进度不互通 |
| 排行/PK/成就/签到 | 全部无 |

## 三、缺口全表（三层留存循环）

| 层 | 模块 | 缺口 | 游戏价值 | 备注 |
|---|---|---|---|---|
| 核心 | 结算叙事 | 「NEW RECORD!」破纪录动画、历史曲线对比 | 复玩情绪峰值 | r22 已有评级/星级/分布条，只差记录对比 |
| 元 | 存档/进度 | 每关星级/分数存档、通关解锁链、继续闯关 | 回归理由 | localStorage 即可 |
| 元 | 生涯档案 | 总时长/总消耗/动作计数/连续打卡日历/周报 | 健身记账感（天天跳绳留存核心） | |
| 元 | 成就/勋章 | 全 PERFECT 局、100 连击、百局、晨练、收藏家…10 枚起 | 收集欲+炫耀点 | |
| 元 | 元进度/经济 | 星星货币：装扮/角色/特效/爆开图案解锁（现免费全开） | 长期目标 | 与现有装扮系统衔接 |
| 元 | 每日内容 | 每日一曲、签到、任务（3 局/50 连击/全勤） | 打开习惯 | |

## 四、PK 三方案对比

| 方案 | 玩法 | 基建成本 | 反作弊 | 评价 |
|---|---|---|---|---|
| **影子挑战（异步）** ⭐ | 对手一局的判定时间轴存成「影子数据」（几 KB），同谱面竞速，实时显示对方进度条/连击/冲线时刻；挑战码/链接分享 | 零后端（或轻后端存影子） | 低：时间轴即合法性证据 | 天天跳绳没有的差异化点，首推 |
| 同屏双人 | 一个摄像头拍两人（classifier 多人化）或一键盘一摄像头，分屏比分 | 零后端 | 无 | 家庭/课堂场景顺手做 |
| 实时在线 PK | WebRTC 房间约战（remote.ts 已有 PeerJS 底子），实时比分 | 信令/房间服务（轻后端） | **高**：客户端算分可伪造 | P2 再做 |

**设计原则**：排行榜/PK 上线前必须先有合法性校验（上传判定时间轴做节奏合理性检验），
否则榜单变「修改器大战」，反伤真实玩家。

## 五、路线图

| 阶段 | 内容 | 成本 | 依赖 |
|---|---|---|---|
| **P0 档案层** | 进度存档+每关 PB+破纪录动画+打卡日历+成就 10 枚+星星货币解锁装扮+生涯统计+结算分享海报 | 1–2 天 | 纯前端 localStorage |
| **P1 PK** | 影子挑战（挑战码/链接）+ 同屏双人 | 2–3 天 | 零后端 |
| **P2 云端** | 登录+云存档（打通 TV/手机）+周榜+好友+赛季段位 | 1–2 周 | 账号/后端选型（另评） |

推荐顺序：**先让游戏「记得你」（P0）→ 让你「打败别人」（P1）→「全服排名」（P2）**。
