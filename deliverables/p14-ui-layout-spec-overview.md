# P14 · UI 版式规范 v1（TV 优先）— 交付概览

## 本轮做了什么

用户提出「给游戏做一套全新 UI：先定界面版式规范，再逐屏产出可切图的资源」。按「先规格，后出图」的工作流，本轮**只做第一步 A 版式定规**，交付一份可直接拍板的完整规范 + 1 张基准图；逐屏资源是下一轮，未批量出图（放量闸门）。

**本轮未改动线上任何界面或样式，未发布。**

## 关键决策与依据

1. **「全新 UI」= 版式规格重构 + TV 优先适配，不推翻 v1 风格锚点。** 霓虹暗色舞台 + 浅色信息外壳双轨、Joy 图标、分组列表、金圈焦点、强横排均为已确认设计，列入「保护」清单。是否连配色一起换，作为唯一方向项单列待拍板（历史上有 V2 糖果卡通重设计被否决回滚的先例）。
2. **根因是规格缺失，不是美术问题**：字号 202 处声明 / 144 个不同取值 / 130 个各异 `clamp()`；`:root` 只有 14 个变量、无 spacing/type/z-index token；TV 实测 1920×1080 而唯一「大屏」断点是 `min-width:2200px`（**永不命中**），只能靠 `zoom:1.18` × 横排 `rotate(90deg)` × `100dvh` 三重叠加，尺寸无法静态推导 —— 这正是 P13「竞技大厅横幅看起来更宽」的根因（两条横幅 CSS 盒模型实测一致，是环境漂移）。
3. **建立单一缩放因子 `--s = min(vw/1920, vh/1080)`，弃 `zoom`**；TV 与手机字号用**离散档表**不按 `--s` 等比缩（观看距离 3m vs 40cm，等比会压垮 TV 正文）。
4. **TV 最小可读 24u @1080p，硬下限 20u @720p**；现状 9–13px 小字在电视上不可读。
5. **DOM/CSS 项目重新界定「可切图资源」**：底板/按钮/卡片/描边一律纯 CSS，切九宫格位图在 DOM 里会糊、装不下多语言、撑大包体；真正出位图的只有发光/粒子贴图与复杂纹理插画（约 8–12 张），图标统一 SVG 矢量家族。仍给出四个**具名**九宫格边界值（left/top/right/bottom 均 28u）供未来移植引擎，并写明四引擎参数顺序差异与 Cocos 的 SpriteFrame 限制。
6. **老电视内核能力基线**：`:has()`(105+)、`cqw`/`container-type`(105+)、`aspect-ratio`(88+)、`inset`(87+)、`clamp()`(79) 在 Chrome 60–79 上静默失效 —— 现状用了前四个，这是「TV 显示不完美」的第二个技术根因。逐项给了替代写法，与已确认的 JS es2015 降级红线一致。
