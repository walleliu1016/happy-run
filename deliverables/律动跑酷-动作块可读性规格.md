## 0. 结论先行

**这不是 B 版配色引入的回归，而是两个一直存在的结构性缺陷，被暖黄日盘和 TV 观看距离放大了。**

1. **地面踏板被透视压成一条线。** 脚步动作（jump / squat / stomp / run）的踏板是水平贴地平面（`rotation.x = -π/2`），相机高 2.9u。远处 z=120 时垂直投影只有 **0.35px**，到 z=30 也只有 **~4px** —— 在 12 秒预判区里物理上等于不存在。
2. **白色符号叠在最亮的背景上。** 日盘半径 72u、位于消失点方向，实测该区背景亮度 **225/255**；动作符号是纯白 `#FFFFFF`，对比度仅 **1.31:1**，远低于图形可辨所需的 3:1。
3. **面向镜头的空中标记也太小。** 1.95u 在 z=120（距相机 127.6u）投影仅 **10.3px @720p**；1920×1080 TV 上 3 米观看不可辨。

**P16 前后像素实测差异 <7%**（跑道 46.3→43.8、日盘 225.7→218.7、远处亮像素 37.2%→36.8%），所以「补光改暖」不是主因；但日盘由冷青变为亮黄，主观刺眼感增强，且动作色全暖化后 `right #C9834E`、`squat #C4243B` 与暖炭背景同色系，又削弱了一层识别。

修复核心只有一句：**让块自带不透明深底板，与舞台明暗彻底解耦；再把水平贴地的面竖起来。**

## 1. 修复前测量（真实开局，非估算）

| 项 | 数值 | 来源 |
|---|---|---|
| 相机 | `y=2.9u, z=-7.6u`，fov 56°（首关 62°） | `game.ts` 相机初始化 |
| 焦距 | `f = 360/tan28° ≈ 677px @720p`；`≈1016px @1080p` | 透视投影 |

| 地面踏板投影高度 | z=120 → **0.35px**；z=30 → **4px**；z=6 → **30px** | `2.85 × (2.9/d) × f/d` |

## 2. 修复规格（已落地，全部为具名值）

| 编号 | 项 | 修复前 | 修复后 |
|---|---|---|---|
| K1 | 符号贴图 | 深色描边衬底 + 白实心符号 + 主题色光晕（半透） | **不透明深炭圆角底板 `#0B0709`** + 主题色描边 `10px` + 白色实心符号（pad `0.64×W` / air `0.66×S`）；`fog:false` |
| K2 | 脚步踏板形态 | 水平贴地 `rotation.x=-π/2`，`2.3×2.85u`，`y=0.06` | **面向镜头竖立** `rotation.y=π`，`2.05×2.55u`，`y=1.05u`；底缘 `6px` 亮色横带保留「贴地踏板」语义 |
| K3 | 空中标记 | `1.95u`，AIR_Y 1.8 | `2.35u`，高度不变 |
| K4 | 距离补偿 | 无 | `k = 1 + clamp((z-18)/90, 0, 1) × 1.15`，即远处 **2.15 倍**、靠近判定线平滑回落到 1.0；面片基础缩放存 `userData.baseScale` |
| K5 | 日盘构图 | 半径 `72u`、`y=17`、光晕 `scale 150 / opacity 0.35` | 半径 **`52u`**、**`y=26`**、光晕 `scale 110 / opacity 0.22`；给跑道尽头留出暗带 |
| K6 | 玻璃桥面牌 | additive 混合的半透明剪影（会糊） | 复用同家族深底符号牌、`NormalBlending`、`fog:false` |
| K7 | 墙来墙板 | 白墙 + 动作色描边（原本对比足够） | **形态不动**，仅享受动作色提亮 |
| K8 | 动作识别色 | `squat #C4243B`（深红）、`right #C9834E`（暗棕） | `squat #FF5C6B`、`right #FF9A3D`；**仍属暖色家族，不触碰 12 个 `--c-*` 语义 token** |

### 对比度实算（WCAG 相对亮度公式）

| 组合 | 修复前 | 修复后 |
|---|---|---|
| 白符号 vs 所在背景 | 1.31 : 1 | **20.03 : 1**（`#FFFFFF` vs `#0B0709`） |
| 块体 vs 亮日盘背景 | 1.31 : 1 | **11.65 : 1**（`#0B0709` vs `#FFB84D`） |
| 橙描边 vs 底板 | — | 7.68 : 1（`#FF7A1A`） |
| 青柠描边 vs 底板 | — | 16.99 : 1（`#C6FF4D`） |

**关键性质：底板不透明 → 上述对比度与主题、日盘亮度、天气/背景图无关**，四个舞台主题（neon / space / candy / forest）与自定义背景图下都成立。

### 实现约束

- 圆角底板用手写 `quadraticCurveTo` 路径，**不用 `ctx.roundRect`**（Chrome 99+ 才有，电视盒子 WebView 常停 60–79）。
- 新增代码不引入 `?.` / `??`，vite 全链 es2015 降级红线保持。
- 删除已无调用点的 `silhouetteTexture` / `silTexCache` 死代码及其 import。
- 图内不放文字：方块上的动作信息全部由几何符号表达，口令文字仍由 DOM HUD 渲染。

## 4. 边界与待人工精修

1. **本轮不产位图资源**。所有贴图为程序化 Canvas 生成（纯代码、零外部素材），符合 P14「DOM 项目底板/卡片一律纯 CSS 或程序化生成，不切九宫格位图」的判定。发光粒子贴图、复杂纹理插画、SVG 图标家族仍是下一轮 C/D，按闸门先出 1–2 张基准图 → 确认 → 放量。
2. **不承诺「生成即可用」**：程序化符号牌的造型、描边粗细、底缘亮带仍需真人 TV 3 米观看验收后微调。
3. **同帧多车道块仍会透视重叠**（14s 帧中间三块叠在一起）。这是谱面同一时刻多块排布 + `LANE3_X = [-3.7, 0, 3.7]` 的几何结果，属数值策划/谱面错峰范畴，**不在本专家边界**，本轮未改。
4. **APK 不用更新**：改动全在 `src/**`，线上覆盖发布即生效（HTML no-cache，壳只加载线上 URL），旧 APK 打开就是新效果。只有改 `tv-app/**`（按键桥 / gradle / URL 戳）才需要 CI 出新包。
5. TV 真机手感与观看距离验收仍待用户实测。
